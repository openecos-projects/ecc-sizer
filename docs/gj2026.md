# GJ2026：GPU 加速与基于关键路径的缓冲器插入

## 研究背景与年度工作

芯片规模增长使时序优化同时面临计算成本和物理实现约束。缓冲器插入可以降低长线和高扇出网络的负载，但会增加单元数量、面积和传播级数；求解速度、时序收益与修改规模需要共同考虑。

本年度围绕两项工作开展算法与工程实现：面向多个线网的 GOBI GPU 并行求解，以及面向当前关键路径的 Path 缓冲器插入。两者集成到以 OpenDB/STA 为核心的 Sizer，覆盖输入、候选生成、网表编辑、合法化、寄生更新、时序验收与输出验证。

## 任务标志性成果

**GPU 缓冲器插入。** 将多线网的树拓扑、电容、线网 RC 与候选缓冲器模型组织为 GPU forest，按层传播、合并和筛选候选，再将方案转为统一网表编辑计划。GOBI 与 CPU Van Ginneken 保留各自求解算法，共用输入、物理执行和独立评估。求解阶段的 frontier 数量、峰值内存及压缩节省可通过 debug 日志观察。

**基于关键路径的缓冲器插入。** 从 setup/recovery 时序路径发现关键网和共享负载，生成旁支隔离、关键负载缓冲及整网多级树候选，预测延迟和 slew 变化。实测反馈用于更新排序和失败证据。算法把接受条件、候选排序与停止规则分开：接受数值上的正收益，按有效进展补回续搜额度，避免每次微小收益都恢复完整搜索预算。

**统一执行与验证。** 算法不直接编辑设计；共享 buffer repair 管理 ECO、约束、增量 RC/STA、回滚和最终合法化。最终输出通过独立进程重载检查。VG/GOBI/Path 均可独立运行；drv+setup 另作为常规修复参照。报告中的 GPU 和 Path 结果不叠加换型或功耗修复。

## 评测结果

### 评测方法与操作

使用 ISPD26 的 ASAP7 输入，包含 AES、JPEG、Ariane 及其 v2，共六个设计。输入默认位于项目内 `benchmark/ispd26/`，共享平台在 `platform/ASAP7/`。每个算法从原始 `contest.def` 开始，读取同一组 LEF、Liberty、SDC 和 RC 设置。默认评测采用 32 STA 线程；本机 CUDA 设备为 NVIDIA RTX 6000 Ada。

1. 构建当前 CUDA 版本：

   ```sh
   cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_PYTHON=OFF
   cmake --build build -j 8
   ctest --test-dir build -R '^ecc_sizer_' --output-on-failure
   ```

2. 自动运行六设计的初始、drv+setup、VG、GOBI、Path：

   ```sh
   python3 scripts/benchmark_ispd26.py --output results/ispd26-benchmark-20261125
   python3 scripts/benchmark_ispd26.py --output results/ispd26-benchmark-20261125 --report-only
   ```

3. 人工运行时，输入 Tcl 负责标准文件加载，Sizer 负责选定流程：

   ```tcl
   read_lef tech.lef
   read_lef cells.lef
   read_liberty cells.lib
   read_def design.def
   read_sdc design.sdc
   source rc.tcl
   ```

   ```sh
   build/src/Sizer design.tcl --flow gobi --threads 32 --output results/gobi
   build/src/Sizer design.tcl --flow path --threads 32 --output results/path
   build/src/Sizer design.tcl --flow drv,setup --threads 32 --output results/drv-setup
   ```

   若要手工使用与评测完全一致的配置，可先加 `--dry-run` 生成任务，然后执行 `sh results/ispd26-benchmark-20261125/ariane_v2/path/run.sh`。Path 的 benchmark profile 采用阶段末合法化/完整验证和增量分析；普通 `--flow path` 使用通用默认配置。

4. 自动评测会独立读回输出 DEF，检查放置、供电、禁止单元、时序、电气违例和 PPA。成功后删除 DEF/Verilog/ODB，仅保留输入脚本、日志与结果 JSON。

本轮评测日期：2026-11-25。

### 结果分析

六设计共 30 项独立评估全部通过，GOBI 六例均使用 CUDA，无 fallback。GOBI 相对 VG 的求解阶段耗时比为 3.46～138.85 倍。两者算法和输出方案不同，不能将求解加速等同于相同质量下的完整流程加速。

Path 的 WNS 改善为 71.91%～98.49%，TNS 改善为 60.71%～99.15%，新增 26～385 个 buffer。残余时序及电气违例见表格，低插入数不代表修复完成。

Path 算法时间包含搜索、增量更新及最终合法化/验证，排除输入加载、输出和独立复评。Ariane v2 本轮算法时间为 177.268 秒，完整进程为 206.28 秒。当前没有搜索时间上限，停止由续搜额度决定。共享主机负载会影响耗时；本轮使用 GPU 1，设备 UUID 见结果目录的 `launch.json`。后续重点是大设计候选生成与刷新开销，以及候选收益和 buffer 数量的权衡。

原始日志、独立评估、命令与生成表保存在 [ispd26-benchmark-20261125](../results/ispd26-benchmark-20261125/)。六设计 drv+setup/VG/Path 对照见 [benchmark.md](benchmark.md)。
